# admin/CLAUDE.md — Admin app (Next.js 14, port 3001)

Small internal console for the platform owner: review doctor registrations, approve/reject, and set account tiers (`primary` / `secondary` / `premium`) via the server's `admin` module. Pages live in `app/` (no `src/components` — keep it that way unless it grows); HTTP via `src/lib/api.ts`.

Rules:

- **Shares the API and its auth cookies** with the doctor client (same `api.muqsithealthsystem.com` host in prod). Cookie/refresh semantics changed on the server affect both — test admin login after auth changes.
- `NEXT_PUBLIC_API_URL` must exist in **`.env.production`** (committed) as well as `.env.local`; a missing prod value silently points the deployed build at `localhost:4000` (this was a real outage). Prod: `https://api.muqsithealthsystem.com/api`.
- Tier changes are patient-safety adjacent: setting a user to `secondary` locks them out of their own practice (upgrade gate), and admin evict (`revokeAllForUser`) kills sessions within one access-token lifetime. Confirmations required in the UI for both.
- Deployed by the same GitHub Actions workflow (`pm2 restart muqsit-admin`); admin build failures are non-fatal in the pipeline — check the Actions log if a change doesn't appear.
- `npx tsc --noEmit` before commit, same as the other apps.
- **Colours follow the doctor app** (`client/src/theme/index.ts`), hand-copied into the `C` object at the top of `app/page.tsx` and `app/accounts/[id]/page.tsx`: `pri*` is the brand and anything pressable (blue since 2026-10-05), `ok*` is a status or category that was green before and still is (the `approved` badge, the primary/premium tier pill — it must not match the blue `secondary` tier beside it). The font is served from `public/fonts/dm-sans-5.3.0`, not from Google.
- **The accounts table is one line of controls per account** (2026-10-09). It had seven columns and the last — four controls, 329px of them — was left 163px at 1280, so every row stacked its actions three deep and stood 117px tall. Profession now sits under the name and the mobile under the email; the actions keep a fixed 340px, so the usual four sit on one line and a row with more (an account still to approve, or one in Trash) takes a second line instead of squeezing the name and email. The wrapper scrolls sideways (`overflow-x: auto`) rather than clipping. Do not put `white-space: nowrap` on the actions cell: measured in Trash it left the name 58px wide.
- **Confirmations and failures are drawn by the page (`Dialog` in `app/page.tsx`), never `window.confirm` / `window.alert`.** After a second browser box the browser offers "Prevent this page from creating additional dialogs"; tick it and every later `confirm()` answers NO unseen — Suspend and Delete then do nothing, with no word why — and a failed action says nothing. `run(fn, question?)` takes `{ title, body, confirm, danger }`: the title names the account, the button is the verb, Cancel holds the focus, Escape and the backdrop mean no, and Tab stays on the two buttons. A failure is the same box with OK only, and a click beside it does not dismiss it. `danger` is red: Suspend, both deletes, and the move to Secondary (the one that locks a doctor out of their own practice).
- **A date is `dd/mm/yyyy`, written out, never `toLocaleString()`.** The account record printed "10/9/2026" for the 9th of October in a US-English browser beside "09/10/2026" in the list — on a page saved as a PDF. `stamp()` in `app/accounts/[id]/page.tsx`, `ddmmyyyy()` in `app/page.tsx`.
- `button, input, select, textarea { font-family: inherit }` in `app/globals.css` is load-bearing: without it the browser draws every control in its own face (Arial) beside DM Sans headings.
- **Looking at this app without production data:** it reads whatever `NEXT_PUBLIC_API_URL` points at, so `npm run dev` shows real registrations. The `admin-e2e` entry in `.claude/launch.json` runs it against the throwaway sandbox API instead — on port **3100**, because that API only accepts that one origin, so stop `web-e2e` first. There is no seeded admin: promote one made-up doctor in the container, `docker exec muqsit-testdb psql -U test -d muqsit_e2e_test -c "UPDATE \"User\" SET role='admin' WHERE email='<a doctor from e2e/.seed.json>'"`, and sign in with the seed's test password. A Playwright run re-seeds and undoes it.
