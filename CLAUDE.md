# Muqsit Health System — CLAUDE.md

## ⚕️ PRIME DIRECTIVE — medical software, patient safety first
Doctors in Bangladesh prescribe real medication through this. These rules beat every skill and every default:
1. **Never invent or guess clinical content** (formulas, ranges, units, dosing, score cutoffs, alert text). Verify against the source or ask the user (a physician).
2. **Never silently lose or transform patient data.** No destructive migration, no dedupe that can drop a finding; deleting needs an explicit action + confirm (+ Undo where built).
3. **Scoping is a safety boundary.** Every patient-data query is doctor-scoped; cross-practice access only via Assistant (workstation) or Supervised doctor. Patient DELETE is owner-only, always.
4. **Print/PDF is a legal document.** Fits the page, never truncates, shows exactly what was entered. Check print preview after touching `client/src/lib/prescriptionDoc.ts`.
5. **Calm clinical UX:** `C` palette, clear empty/loading/error states, forgiving input, silent retry on flaky networks.
6. **Verify before claiming done:** typecheck + both test suites + the flow exercised at :3000/:4000; report honestly what was not verified.
7. **Keep the CLAUDE.md files and `docs/DOMAIN.md` current** in the same commit as any major change.

## Project Snapshot
- Monorepo, three apps with their own `package.json`; root only orchestrates (`concurrently`).
- `client/` Next.js 14 + React Query (:3000, doctor app) · `admin/` Next.js 14 (:3001) · `server/` NestJS 10 + Prisma 5 + PostgreSQL (:4000, REST under `/api`, cookie JWT).
- Request flow: `client/src/lib/api.ts#apiFetch` (sends `X-Workstation`) → Nest controller (`JwtAuthGuard, WorkstationGuard`) → `@WorkstationDoctorId()` → service → `PrismaService`.

## Architecture & Conventions
- **Server:** one Nest module per domain in `server/src/<domain>/` (`*.controller.ts`, `*.service.ts`, `*.module.ts`, `dto/`). `ValidationPipe({ whitelist: true })` drops any field not declared on the DTO.
- **Client:** App Router pages are thin shells → `src/components/Muqsit.tsx` → `TabRouter.tsx`; editor state in one store, `src/context/MuqsitContext.tsx`; server state in `src/hooks/use*.ts` (React Query); pure clinical logic in `src/lib/*.ts` with a co-located `*.test.ts`.
- **Clinical logic gets a unit test** (same-medicine matching, offered doses, which alert fires). A red test is a clinical regression — check the source before changing the expectation.
- **DB:** one shared PostgreSQL on the VPS, reached through an SSH tunnel the user runs. `P1001` = tunnel down, ask the user; not a code bug. Applying a migration locally migrates production.
- **Deploy:** push to `main` → `.github/workflows/deploy.yml` builds and `pm2 restart all` (~2–3 min). It does not run migrations. Since 2026-10-16 a failed server or client build stops it before the restart and the Action goes red; before that, a failed build was restarted into production and reported as a success. **A red deploy is NOT a safe state — fix it at once:** both builds empty their output folder before compiling (`next build` its `.next`, `nest build` its `dist`), so after a failed client build the running app may already be serving missing pages, and after a failed server build the next restart of the API (a crash, a reboot) finds no `dist/main.js` (independent review, 2026-10-17). Building into a separate folder and swapping it in on success would close this; not done yet. If a VPS `package-lock.json` drift blocks `git pull`: SSH in, `git checkout -- <app>/package-lock.json`, re-run the Action.
- **Branches:** exactly two, `main` and `dev`, locally and on GitHub (product owner, 2026-10-13). Work on `dev`; release by fast-forwarding `main` to it — that push is the deploy. No feature, design, backup or `claude/*` branch is left standing: a safety copy is a stash, a patch file or a bundle under `.git/`.
- **Dates:** stored/shown `dd/mm/yyyy`, `ptDate` is ISO; `ddmmyy` shorthand accepted.
- **Git identity:** every commit and push as `Muhammad-AIUB <mjubayer.aiub@gmail.com>`. The machine's default is wrong — check `git config user.email` and `gh auth status` before committing and before pushing.
- Commits: conventional (`fix(scope): …`), ending `Co-Authored-By: Claude <model> <noreply@anthropic.com>`.
- Every route change updates `docs/API.md` in the same commit.
- Reply to the user (a physician) in Bangla; code and comments stay English.

## Patterns We Do Not Use
- We do not run Prisma Migrate (`prisma migrate …`), and there is no `prisma:migrate` script to run by habit any more (removed 2026-10-16): against this database `migrate dev` finds a schema with no migration history and offers to reset it. Edit `schema.prisma`, write an idempotent `server/prisma/manual-<name>.sql` (`IF NOT EXISTS`), apply with `db execute`, regenerate — the DB is shared with production, so only additive changes.
- We do not run `prisma generate` with the API up. Kill the :4000 process first — Windows locks the query-engine DLL (EPERM).
- We do not take the doctor from `req.user.id` or a request body. Use `@WorkstationDoctorId()` — `WorkstationGuard` is the only place that decides whose practice a request acts on.
- We do not resolve a practice again inside a service. Pass the resolved `doctorId` in — a second resolver leaked another practice's activity feed (fixed 2026-08-27).
- We do not add a client field without adding it to the DTO — otherwise it is "saved" and silently dropped.
- We do not assume a `manual-*.sql` file was applied. Check the DB — `manual-opd-token-unique.sql` / `manual-ipd-bed-unique.sql` may still be unapplied.
- We do not leave a table created as `postgres` with that owner. Run `ALTER TABLE "X" OWNER TO exhort_user;` — otherwise the app gets `42501 permission denied`.
- We do not parse a stored date with `new Date(str)`. Use `client/src/lib/dateInput.ts` — JS reads `03/06/2026` as 6 March.
- We do not put `medicines` in `schema.prisma`. It is a raw table queried with parameterised `$queryRaw`.
- We do not reword, add or "fix" entries in `client/src/data/rxAlerts.ts`. Every message is verbatim from the physician's rule sheets.
- We do not print or persist prescribing alerts. They are derived live; `prescriptionDoc.ts` has no alert input, pinned by tests (physician's decision).
- We do not `increment: 1` a habit/phrase `patientCount`. It counts distinct patients, taken from the record.
- We do not let a derived-feature write fail a prescription save. It runs awaited, in try/catch, after `prescription.create`.
- We do not hard-delete clinical documents or add DELETE routes for learned suggestions. Use soft removal (`removedAt`) / `hidden`.
- We do not extend `WorkstationsService.resolve` for IPD ward-team logins. That would hand a ward nurse the whole practice's OPD records.
- We do not send new per-admission data through the IPD `clinical` PATCH. It replaces the whole column; give it its own route (see `/ipd/:id/analogue`).
- We do not store upload URLs minted on localhost. The dev DB is production; `upload.service.ts` refuses them.
- We do not instruct manual deploys or builds on the VPS. Push to `main`; only DB migrations are manual.
- We do not point a test at `DATABASE_URL` from `.env`. It is production behind the tunnel; DB-backed tests use the container on `127.0.0.1:5544` and `assertTestDatabase()` refuses anything else. `prisma db push` is allowed only inside `server/test/support/setup-db.js`, which forces both URLs to that container.
- We do not retry a flaky test. A test whose outcome varies is a defect; find the cause (clock, order, timeout) with `scripts/test-repeat.mjs`.
- We do not change a test to make a real defect pass. It stays as `it.failing` / `it.fails` with a `DEFECT-` comment until the code is fixed.
- We do not colour a status with the brand colour. `C.pri` (blue) is for what can be pressed or is selected; "done / normal / saved / stable" is `C.ok` (green). The brand was green until 2026-10-05 and doubled as "fine" — a normal BMI and a Save button were the same colour.
- We do not load a font, a script or a stylesheet the UI needs from a third-party CDN. A hospital network that blocks Google turned the whole app to the system font; DM Sans is in `public/fonts` of both apps, and the E2E request guard allows no outside origin.
- We do not use an emoji as an icon, and we do not turn a text glyph a doctor reads (✎ ⊘ 💊 ★ ↺ ↳ ℞) into one. Chrome icons are `client/src/components/common/Icon.tsx`; the list of glyphs that stay text is in `client/CLAUDE.md`.
- We do not make a `div` or `span` clickable without `pressable()` (`client/src/lib/a11y.ts`), or ship an icon-only button without an `aria-label`. 26 controls had no keyboard route and 16 buttons had no name.
- We do not change a colour, size or spacing in `prescriptionDoc.ts` as part of an app restyle. It imports no theme on purpose; its five accent rules were moved to blue once, by the physician's decision, with the whole-document snapshot updated in the same commit.
- We do not call `window.confirm` or `window.alert` in the doctor app. Use `confirmAction()` / `tell()` (`client/src/lib/dialogs.ts`); the admin console draws its own since 2026-10-09 (`Dialog` in `admin/app/page.tsx`). The browser lets a user switch its boxes off for the page — after that a `confirm()` answers "no" unseen and an `alert()` says nothing, including "the prescription was saved but could not be printed". And because the app's own question does not freeze the page, fix what is being removed before the `await` and re-read the list and the loaded patient after it (2026-10-06).
- We do not set `inert` — or any attribute React does not manage — through a bare ref. Use `useInert()` (`client/src/lib/inert.ts`). React re-uses the wrapper's DOM node for the content it wrapped, and a hand-set attribute stays on it: the editor came back from the patient gate with a patient chosen and nothing in it could be typed into; `Lock` had the same trap (2026-10-06).
- We do not name a form box only by its placeholder. The caption stays above the box (`fieldLabel`); on the admit form Bed, Room no and Cabin / ward no were three numbers in a row with nothing left to say which was which.
- We do not show a failed list as a line of red text. `LoadError` says what did not load and offers Try again; without it the only retry is reloading the app with a prescription half written. Never the raw `error.message`, never "Is the API running?".
- We do not draw every message of one line in one colour, or say on a line that goes that a save failed. The line under the Save buttons was `C.ok` green for all it ever said — "Save failed: …", "Draft NOT saved. Is the API running?" and the refusal of a pad it cannot write among them — and it went after three seconds, under the print sheet after Save & print (release review, 18/10/2026). It holds its KIND with its words (`SaveNotice`); a save that failed, or was refused for anything but an empty form, is a `tell()` box in the doctor's words (`whyNotSaved`, `client/CLAUDE.md`); and a throw after the prescription was created is never called "not saved", and does not stop the visit being marked complete — either way the doctor would file it twice.
- We do not size anything against the screen with `vh` / `vw` in the doctor app. The whole page is drawn at `zoom: 1.12`, and a viewport unit inside it is scaled too: `100vh` is 112% of the screen. The sign-in page always scrolled, and the image viewer opened a portrait order sheet with its top and bottom edges off the screen and its last line under the zoom bar. A page uses `.screen-fill` / `.mobile-shell-fill`; a popup takes `maxWidth` / `maxHeight: "100%"` from the padded veil it stands in (`client/CLAUDE.md`, the page-zoom rule; 2026-10-09).
- We do not add a pointer's travel or a measured rect to a `position: fixed` coordinate, a `translate()` or a scroll offset without `zoomScale()` (`client/src/lib/dropdownAnchor.ts`). The first two are in screen px, the others in the page's own: the medicine list hung 12% off the line being written — 54px low for a line 433px down the screen, which put it under the NEXT medicine — and a dragged sheet ran ahead of the finger holding it.
- We do not ask the browser to write a date, a time or a number without naming the locale (`toLocaleString()`, `toLocaleDateString()`). It answers in the machine's own language and order: `10/9/2026` for the 9th of October beside this app's `09/10/2026`, three different orders on two ward screens, and an absolute neutrophil count of 1500 written `1.500` in a German browser. A timestamp goes through `client/src/lib/stamp.ts` (`9 Oct 2026 · 17:04`), a calculator's number through `grouped()` (`client/src/lib/calculators/format.ts`); the admin console has `stamp()` / `ddmmyyyy()` of its own.
- We do not draw a control over a page that is open to be read. In the image viewer the arrows sat on a phone-wide order sheet and the zoom bar on its last line; at fit the whole page is on the screen with room kept for the controls (`LIGHTBOX_CSS`).
- We do not open anything over the app without `useDialog()` (`client/src/lib/useDialog.ts`). A popup that only listens for Escape leaves the focus on the page underneath: with the print sheet covering the screen, three presses of Tab reached the patient chat's message box, where Enter sends. A new popup's test runs `itKeepsTheKeyboard()` (`client/src/test/dialogKeyboard.tsx`), and one that shows an `<iframe>` listens for keys inside it too — a key pressed in a frame never reaches the app (2026-10-12).
- We do not hand the focus back to a button that SAVES. Every popup returns the focus to what opened it, and pressing an opener again normally just opens the popup again — but the print sheet is opened by "Save & print", and with the focus back on it Enter or Space (the key that scrolls a page) filed the same consultation as a second Prescription row. That sheet closes with the focus on the page (`useDialog(…, { returnFocus: false })`); `e2e/tests/print-sheet.spec.ts` holds it with a real keyboard (2026-10-12, caught in review before release).
- We do not let a listener on the whole document guess what an element is for. A caption that puts the cursor in its box is a `<label data-caption>`; the first rule was "any label with no control in it", and "Mirror devices" — a switch drawn as a label — sent the cursor into the patient search on every press. An element opts in by saying what it is, and a thing that is pressed is a `<button>`.
- We do not cut a medicine's label at its END to fit a narrow column. A label starts with its dosage form: `Tablet. Entaliv 0.5 mg` and `Tablet. Entaliv 1 mg` both became `Tablet. Enta…` on a phone's health-trend chart — two bars under one name. The dosage form gives way first, then the end of the brand; the strength is the last thing cut (`nameLines` in `client/src/lib/timelineLabel.ts`). And "the dosage form" is not whatever stands before the first full stop — `Pot.` and `Sod.` are part of a name, and left off they made potassium and sodium chloride one; `IV Infusion.` is a form the app does not know by name, and treated as part of the name it took the whole line from the brand. Three reviews found three such cases; a property over many names found two more that examples had not.
- We do not promise, from a rule for ONE name, that two names will come out different. Two lines of thirteen letters do not hold every label, and whatever a rule leaves off, some pair differs in exactly that: with the rule above in place a tablet and an injection of one medicine and strength were one name on a phone's chart, two salts of calcium another, and four parameters of Hb electrophoresis four lanes all called `Hb / Electrophores…` — while the code and three documents said "never" (fourth review, before release). The names of one chart are laid out TOGETHER (`namesApart`): any that come out the same are written again so that what they differ in is what is shown. And a property that says "never" is run over pairs BUILT to be mistaken for each other — the one that passed had left out every pair of brands sharing three letters.
- We do not let one step of a fix undo another. The first `namesApart` took whichever of two ways applied, round after round: of four strengths of one tablet it told one pair apart by showing their last part, which made them the same as the other pair, and the next round turned it back — two strengths under one name again, and `12.5 mg` on a line by itself as if it were the whole strength of a 5 + 160 + 12.5 tablet (fifth review, before release). A step is taken only when it leaves FEWER pairs alike on the whole chart than before; what is brought into view keeps a mark beside it; and each case found that cannot be told apart in two short lines is written down as a failing test (`DEFECT-HM-NAMES`), not left for a reader to find. And we say of a rule only what it holds: "fewer pairs alike" ends the work and stops two rounds turning each other back — it does not mean a pair once told apart is never put together again, which the code's own comment, a test's name and two documents claimed for a review round.
- We do not cut a number, or part it from its unit, to make it fit — and we do not try a rule about medicine labels only on labels we made up. On the phone chart's names a cut fell wherever the line ran out: `12.5 mg + 500 mg` was shown `12.5 mg + 50…`. And the word a strength parts at was looked for between spaces, while a combination picked from the medicines table has none round its plus (the one label in the tests that came from a real sheet is written so, `Edeloss 20 mg+50 mg`; the table itself was not read for this): `10 mg+160 mg+25 mg` was shown `10…mg+25 mg` — a tablet of 10 mg + 25 mg, to the eye; the unit beside the 10 was the hidden 160's (sixth review, before release). The reviews before it had passed it by, because every example in the code, its tests and three documents was written with spaces: nobody had looked at how a real label writes one. An AMOUNT — a number with the short word after it — is not cut into where a line can hold it, and one too long for that keeps its NUMBER whole (the rule's first form did not look for such an amount at all, and `1,200,000 IU` was cut to `1…`: seventh review); a decimal point is never parted from its number (`.5 mg` shown as `5 mg` is ten times the dose); and the rule is held by a property over labels written both ways (`client/src/lib/timelineLabel.ts`). (On a WIDE screen a name is still one line cut at twenty characters wherever that falls, as in production — `Tablet. Metformin 5…` for 500 mg; closing it takes the two-line names there, which changes the chart the physician knows: `FUNCTIONAL-AUDIT.md`.)
- We do not say "every" of what a sample has shown, and we do not take "the labels differ" for "the labels tell them apart". A property that drew a few thousand random charts a run said every pair on a chart of confusable medicines was told apart, and passed through two reviews — while one chart in a hundred of a single shape, a medicine in two forms and two strengths, was not four names; and where the names did differ, a dose change could read `10 mg+160 mg+…` on both bars (seventh review, before release). A shape that matters is COUNTED, whole, over fixed pools (1,210,776 charts in `timelineLabel.test.ts`), and what is counted is what a doctor reads off the label: two strengths of one medicine never show the same numbers. And the pools are part of the claim: "one of them written another way" was first counted over four ways of writing a form, all of them words the app knows — over the ten forms of the test beside it, 288 charts in half a million still read `10 mg+160 mg+…` for 12.5 and for 25 (eighth review). A test's name says what the test tries.
- We do not cut a strength without looking at the other strengths of that medicine on the chart. Laid out one at a time, two labels that differed in something else — the form typed `Tablet` with no full stop, or another form altogether — each cut a long strength at its end, and a dose change read `10 mg+160 mg+…` on both bars; the rule that compares strengths ran only for names that had come out identical (eighth review, fixed after the release it reviewed). Where another strength of a medicine is on the chart, its strength has the second line to itself and is cut by what it has to be told from (`layOut`, `medicineOf` in `client/src/lib/timelineLabel.ts`). And a fix for one thing a label says is checked against the other things it says: that line was taken from the END of the brand, and for one round on `dev` `Tablet Exforg…` stood over a strength with `Exforge` on the same chart — the dose told apart, the medicine no longer (ninth review, before release). A guard written for "what the two medicines share" then missed the shorter of the two names, and a name behind a form the app cannot set aside (tenth review). The rule that stands needs no judgement, and so it can be counted: the strength takes the line only where the new lines show as much of the medicine's name as the name shows by itself — counted against the release, not one label in a million and a half shows less.
- We do not take a property that has passed for a rule that is held. "Two names that are different are never written the same" draws 20,000 pairs a run, a different 20,000 each time. The seventh review's change to the rule under it left about one pair in eighty thousand alike — the test failing some one run in four — and it went out in a release: the run that was looked at had passed. On 2026-10-13 a run failed; drawn two million times, the property left 27 pairs alike where the code before that change left none. Nineteen were a defect in the rule and eight a limit, now written down; and drawn that far, "a number is never shown in part" gave up two labels of its own. A sampled property is run ONCE at a hundred times its budget when it is written and whenever the rule under it changes; a red property is read, not run again (`FC_SEED` replays it); and a check by breaking the code proves nothing while a test under it fails at random — any red run counts as a caught break.
- We do not bring a language feature into the page every doctor opens without asking what a browser that lacks it will do. The amount rule was first written with `\p{…}` classes and `matchAll`, neither used anywhere else in the doctor app — and a browser without the first (Firefox before 78) does not show a wrong label, it fails to load the page. It is written with plain classes and `exec`, and a test reads the file for both (seventh review, before release).
- We do not put a space, or anything else, inside a number in order to show it — and we do not guess from a string which comma is which. The Investigation popup spaced every comma of a stored result, so `ANC 1,500` was shown `ANC 1, 500`; the first fix kept together whatever LOOKED like a grouped number, and showed ETT's `METs:10` and a report beginning `150 bpm` as `METs:10,150 bpm`. The catalog says which values can hold several parts — only a test that has, or ever had, several boxes — and everything else is shown as stored (`client/src/lib/findingParts.ts`). A display rule that is right for one test's values and wrong for another's is not a fix, and neither is one that is tested beside the line that applies it: the panel's own line was wrong twice with the rule's tests green.
- We do not plot part of a number. The parts of a stored result are joined by commas — a comma and nothing else, no space — so a comma with a digit directly on each side of it cannot be read: `WBC:1,200` is 1,200, or 1.2, or a 1 and another box's 200. What stands on either side of such a comma is not plotted (`client/src/lib/numericInvSeries.ts`); a comma followed by a space is punctuation, and what a typed comma MEANS is the physician's to say — which leaves a NUMBER typed with a comma and a space inside it (`1, 200/cmm`) read as its first part, as production reads it, and that is written down as a failing test (`DEFECT-HM-SPACED`) rather than guessed at. It took three reviews, each finding a wrong number already in production: `1,200` drawn as 1; then `1,200/cmm`, because the guard knew one shape of what follows; then a ferritin typed `>2,000` drawn as 0, because nobody had looked at the comma from its OTHER side. A guard is written for the thing itself, not for the one case that was reported — and tested over every box of the catalog.
- We do not convert, or record, a number we have not read whole. `parseFloat` reads the start of a text and stops: in a two-unit result box a viral load typed `1,20,000` copies/mL was converted from its first group and recorded — and printed — as `0.18IU/mL` (in production until the release that carried this). Only a whole, plain number is converted; anything else is recorded exactly as typed, in the unit of the box it was typed in (`client/src/lib/twoUnitValue.ts`). Never `parseFloat` / `parseInt` on something a doctor typed without first checking that ALL of it is the number.
- We do not call a rule tested by an assertion that would hold with the rule broken. "The calendar's arrows choose no date" passed with nothing typed — and what the rule protects is the half-typed result that choosing a date files. A test that something does NOT happen starts from the state in which it would, and is checked once by breaking the code.
- We do not shrink a drawing that carries numbers to fit a narrow screen. The health-trend chart was drawn at half size on a phone and a lab value stood 5px tall — a number a doctor cannot read is one they will guess. It keeps its size and scrolls sideways; its names stay put as a second window on the same drawing.
- We do not let a key that MOVES also CHOOSE. In the Investigation calendar the arrows move along the days and only Enter, Space or a click chooses one, because choosing a day files whatever is half typed under the old date.
- We do not keep a second copy of loaded data for a button to act on. The personal note held a `draft` that an effect copied the loaded note into, with a "changed" flag beside it. The copy arrived one render late — Print pressed in that instant printed an empty note and skipped the question a note with sensitive text must ask; no hand is that fast, a test was, one run in four, and `scripts/test-repeat.mjs` is what named it: a test whose outcome varies is telling the truth about the code. And Save marked everything "saved", also what was typed while the request was on its way: those words were thrown away, or left on the screen looking saved while Print read the older text. The note has ONE text — what was typed, else what is saved — which the box shows, Save sends and Print prints; and a save clears only what it SENT (`client/src/components/prescription/PersonalNote.tsx`, 2026-10-12).
- We do not let an open popup follow the editor's patient. The personal note was handed `currentPatientId` on every render; another device moving the editor on (device mirroring), or a patient still loading from the OPD queue, changed it under the open box — and words typed for one patient were saved into the next one's note, under the next one's details. A popup that writes to a patient is opened FOR that patient: the id and the details are fixed at the press, and it stays theirs until it is closed (fourth review; in production until the release that carried this). The button that opened it does nothing while it is open — it is still in the page behind the popup, where a screen reader or a voice command can press it, and pressed again it re-pointed the open box at whoever was in the editor (fifth review).
- We do not take a field's report of its own text as an edit. The note's editor reports on every blur, typed in or not, and an untouched note asked about unsaved changes; compare with what is held before calling anything changed.
- We do not let a list that is being TICKED be replaced under the doctor. "Add Bulk Medicine" asks for the doctor's medicines on every opening, because a prescription saved in between changes the counts — and a cached list shown at once, with the newer one landing a moment later, re-sorts the rows as a finger comes down: the tick lands on the medicine that moved into that place. While a request is on its way the box says Loading and draws no rows (`bulkBoxState`). The first version left "nothing is kept between openings" to the cache's own timer (`gcTime: 0`); a test that reopened the box at once still found last time's list in it (2026-10-13, before release). The search broke the same rule a round later: its rows are drawn a moment behind what is typed, so that a long list does not hold up typing — and Tab reached the first row of the list as it stood BEFORE the search, where `napa`, Tab, Space ticked another medicine. The rows are brought up to what is typed before the keyboard lands on them (`catchUp`; second pass of the independent review, before release).
- We do not draw "nothing here yet" for anything but a list that is HERE and EMPTY. "Not loading and not failed" is not "loaded": React Query does not ask at all while the browser says it is offline — nothing is fetching, nothing has failed, nothing is there — and "Add Bulk Medicine" told a doctor with years of prescriptions "No medicines yet. They appear here after you save prescriptions." So did an answer that was not the list (an empty body, a hospital Wi-Fi's sign-in page in its place), which a reader that never throws had turned into an empty list, and a failed refresh with an older list still held. The fetch asks whatever the browser says (`networkMode: "always"`) and so fails where it can be said; an answer is checked to BE the list before it is read as one; and an error is drawn before any data (`useBulkMedicines`, `BulkMedicineModal`; first review, before release). A reader that never throws needs a caller that asks what it was given.
- We do not say "the same" of what we compared in part. "Add Bulk Medicine" skips a medicine whose first line is on the pad — the physician's rule, so that no LINE is written twice (the same medicine at another dose is another line, and is added) — and said "already on ℞ with the same instruction", while the pad held that medicine WITHOUT the tapering lines shown in the box. The skip was right and the sentence was not: what is compared for the skip (the first line) and what is said about it (the whole instruction) are worked out separately now, and the line beside the + says when the tapering lines differ (`bulkToRxItems`, first review, before release).
- We do not hand a "fail silently" rule to a second caller without the thing that made it safe. The "Your usual" dropdown may lose a medicine's generic to a failed catalogue lookup, because the ℞ pad has a second source for it — a partial one: the medicine results loaded for what was typed. The bulk list reused that lookup, try/catch and all — and it has no second source, so a medicine added from it would have gone onto the pad with its contraindication warning switched off, several lines at once and nothing on screen to say so. There the lookup throws, and the box says the list could not be loaded (`listAll` does not catch what `attachGenerics` throws; `list` does — first review, before release).
- We do not put a flag that names one feature on what another feature made. The design for "Add Bulk Medicine" said its lines should carry `fromHabit`, as a line picked from "Your usual" does — and that flag is what makes a save write `N of M ℞ lines inserted from "Your usual"` to the activity feed, a sentence about how the prescription was written that would not have been true. Before reusing a field, read every place that reads it.
- We do not break code in the checkout the dev servers are watching, to see whether a test catches it. The dev database is production. For the seconds a deliberately broken file is on disk, `next dev` serves it to whoever has `:3000` open and nodemon restarts the API with it — a + that fills in a dose nobody wrote, a list with its doctor filter taken off. Tests are checked by breaking a COPY of the sources with `node_modules` linked in (a junction; unlink it before deleting the copy), which runs the same suites. Several rounds were run in place before this was seen for what it is — pure display code on the health-trend chart, and on 2026-10-13 thirteen changes to the + button itself, minutes after it had been wired into the pad; nobody was prescribing through those seconds, which is luck and not a control.
- We do not call a query fast, or a feature finished, that has only met the six rows of a test table. "Add Bulk Medicine" asked the medicines catalogue for each brand by a pattern (`ILIKE 'napa%'`), as the "Your usual" dropdown always had for its four medicines — and every pattern is tried against every row. Three reviews, 1,800 unit tests and 22 browser journeys were green; the test catalogue has six medicines. Measured against a made-up catalogue of 35,000 (2026-10-14, before release) the box took 5 to 7 seconds to open for a doctor with 200 medicines and over a minute for one with 2,000. A read that grows with a real table is run once against a table of that size before it is called done — a throwaway script against the load-test database is enough (`muqsit_load_test`, never the tunnel) — and what was NOT measured, here the production catalogue itself, is said.
- We do not take `next dev` for how fast a screen is — or one reading for a measurement. The dev server draws every component twice and runs every effect twice (`reactStrictMode`): the "Add Bulk Medicine" box asked for its list twice there, the first request thrown away, and took 4.6 s to open with 2,000 medicines where a production build of the same code asks once and takes 1.9 s. The first reading — "the request takes 1.7 s in the browser", with 300 medicines — did not repeat: a quiet machine gave 0.26 s and the production build 0.2 s, and the next step would have been spent on a server that was not slow. A screen is timed on a production build in a directory of its own, pointed at the test API (`NEXT_DIST_DIR`, `NEXT_PUBLIC_API_URL`); each action several times, the median kept; and two ways of doing a thing in alternation on ONE build — single readings said a tick was twice as slow with the change that was being weighed, and the next run that it was not. Running the journeys on that build also found a helper of theirs that only held on the dev server (Next's route announcer holds the page's title there and nothing in production): a test that tells one thing from another by what the dev server happens to print is checked once against a build (2026-10-14).
- We do not take every answer below 500 for the server's last word, or its text for a sentence written for a doctor. For one round the box's quiet retry skipped all of them and showed their message. A 401 is what `apiFetch` gives when the session could not be renewed just then — on a bad connection the retry is what gets the list — and "Unauthorized", "Cannot GET /api/…" and "ThrottlerException: Too Many Requests" are the framework's words. One refusal is worded for a person, the 403 of `WorkstationGuard`: it alone is shown as written and not asked for again (second pass of the independent review, before release).
- We do not take Chromium's word for another browser where Chromium covers for the page. A row of the "Add Bulk Medicine" list is drawn a frame after it comes near, taller than the space kept for it, and pushes the rows under it down; Chromium holds the scroll still through that (scroll anchoring), and a browser without it does not — Safari is documented as having none; it was not run. The first fix for "End leaves the row it lands on out of sight, where Space ticks it unseen" asked the row into view once, a frame later — too early — and the journey written for it passed, because in Chromium there was nothing to fix. With `overflow-anchor: none` on the list and rows taller than their stand-in, that journey failed on the fix and passes on the one that stands (asked on each of four frames). The browser suite runs ONE browser: where it does something for the page that others do not, the test switches it off — and what was not run in the other browser is said (third pass of the independent review, before release).
- We do not ask "is this medicine on the pad already?" in two ways. Drug history's "Move to Rx" compared the label letter for letter; the "Add Bulk Medicine" box, written later, compared the medicine as the app does elsewhere. The same entry was a line written twice from one screen and skipped from the other: `tab napa 500mg`, typed at an earlier visit, went on the pad beside `Tablet. Napa 500 mg` at the same dose (in production until the release that carried this). Both ask `sameMedicine` / `MedicineMap` (`client/src/lib/medicineKey.ts`) — how a label was typed, set aside: spaces, capitals, `Tab` for `Tablet.`, a decimal typed `.5`, and since the physician's decision of the same day a label typed with no dosage form as any form of that name and strength; it converts no unit, never sets aside a strength, and never takes two forms for one — and both compare the dose, food and duration by `instructionKey` (capitals and spaces only). For both, a NOTE that reads as the medicine is a line of it with nothing in those three and no tapering lines (an entry whose doses are in its tapering lines was skipped against such a note, and the regimen never reached the pad — review, before release), and a tapering line is not a first line. (How each reads the pad is still its own code, written to that one rule.) And a key that sets typing aside is tried on what typing does to a NUMBER: the first one read the point of `.5 mg` as the full stop that ends a dosage form, and took 0.5 mg and 5 mg for one medicine (review, before release). A rule given to a second screen is given as the same function, not as the same idea written again (2026-10-14).
- We do not keep a way onto the ℞ pad that no screen uses. The legacy drug picker and the static "templates" could not be opened from any screen, and they still held code that wrote a medicine with `1+0+1 · After meal · 5 days` beside it, and whole regimens kept in the app (amoxicillin 1+1+1 for 7 days), onto the pad. The templates had no caller at all; the picker's open flag still rode the device mirror, which no build had set since 2026-06-18. Dead code that writes clinical content is removed, not left for a later change to wire back in (2026-10-14).
- We do not leave out the server's integration suite because only the client changed. `server/test/contract-dto.int-spec.ts` reads `client/src/lib/api.ts` with the TypeScript compiler, and takes only `name: value` options as ones it can read: `apiFetch(path, { signal })`, written in shorthand, failed it — for a change that touched no server file and that the client's own suite passed. It stood unseen through one round of this feature, until the whole verification was run on the final state (2026-10-14). After touching `api.ts`: `cd server && npm run test:int`.
- We do not let a mirror remember what it WOULD write as what it wrote. The ℞ → Drug-history mirror kept "the entries today's ℞ produces" as its own and withdrew them when a line left the pad — but it inserts a block only when the very same text is not there already, so a line the doctor had typed into Drug history by hand that read exactly like a ℞ line (Move to Rx writes the same text) was claimed, and taking the medicine off the pad deleted the hand-typed record (independent review, 18/10/2026; older than that day's change). It now claims only what it inserted (`mirrorClaims` in `client/src/lib/rxDrugHistory.ts`) — and what it owns is part of the VISIT (`rxMirrorOwned`, in the draft and the device mirror): the first fix kept it in one device's memory, and the second review found that a second, mirrored device then never claimed the lines and could not withdraw a medicine it took off the pad. Ownership that a feature depends on travels with the state it describes. And it is decided by the operation itself, not by a second reading beside it: the claim was worked out before the withdrawal it depended on, and a medicine whose taper was deleted was never claimed again (release review). The same review found the mirror's other blind spot: a draft parked yesterday and resumed today kept its ℞ lines at yesterday's date, and under the new "Current = the previous visit" rule an unprinted visit read as the previous one; the resumed draft now tells the mirror those lines are its own, and they are re-stamped to today.
- We do not keep a half-typed value in a popup that stays mounted for the whole session. On examination's new history boxes held what was typed and not added in local state; the popup is mounted once in the shell, so the text waited there for the next patient, and Save added patient A's history to patient B (review, 18/10/2026). A popup's own draft is dropped when the patient under it changes — and on close it is ASKED about, never dropped without a word (the second review found the first fix did exactly that). The question is about the destructive act ("Discard …?", red): the app's question reads Escape and a press beside it as "no", so "Keep it?" made a second Escape the discard (release review).
- We do not leave a transaction that takes a row lock on Prisma's default time limit. It ends an interactive transaction at 5 s and counts the time spent WAITING for the lock, so the lock that keeps every order-sheet page made the writes at the back of a queue fail with a 500 on a busy server — the page was not filed. It surfaced as an integration test that failed "only under load"; run under load on purpose (12 runs, 8 cores busy) it failed 2 in 12 with the exact error, and a test that holds the lock for 6 s failed every time. Such transactions take `ROW_LOCK_TX` (`server/src/prisma/row-lock.ts`, `server/CLAUDE.md`). A test that fails only under load is reproduced UNDER LOAD and read, not run again until it passes.
- We do not let a line that lost its medicine fall onto the medicine above. A `>>>` line belongs to the line directly above it, by position alone — so when that line's NAME was cleared, the pad's reading dropped the nameless line and kept its tapers, and from there everything read them as the previous medicine's: Save & print filled that medicine's name in, the sheet printed the dose under it, Drug history recorded it (physician, 18/10/2026: "dangerous bug"; older than the release that found it). A rule that hangs on position is checked where the position is still known (`rxItemsFromRows`) — and the state is stopped where it is MADE: a medicine with `>>>` lines keeps its name. The first fix only refused at Save, and its review found the same danger by another door (× tidied away the blank line and moved the next `>>>` line under the medicine above), typed vitals moved into a log before a refusal, and one patient's flagged lines left on the next one's pad. Refusing at the end is the second line of defence, not the first. And a rule that hangs on position holds only if EVERY edit that changes position keeps it: the third review found two more doors for a `>>>` line saved before the fix with no medicine above it (× tidying away a blank note above it, ▲ putting a medicine above it at the top), and the kept name put back by row index onto another medicine's `>>>` line after the rows moved under the caret. Such a line is now drawn as a line of its own (`rowsFromRxItems`), and the name goes back only onto the very rows it came from. What is still open — a line the pad cannot write is lost without a word when the pad is drawn again — is written down in `client/CLAUDE.md`, not called closed.
- We do not enable the ECC plugin in this repo. Its hooks have not been checked against these safety rules.
- We do not write a colour as a literal in the doctor app, and we do not darken what is printed. Since night mode (2026-10-15) every colour is a CSS variable from `C` (`client/src/theme/palette.ts`); a literal `#fff` stays white on a night button. `rawColours.test.ts` fails on one that is not on its allowlist with a reason. Printouts, patient images and rich text (PAPER) are the same in both modes (`client/CLAUDE.md`, Night mode).
- We do not import anything with React in it into `client/app/layout.tsx`. It is a server component, and a hook reached from it fails the production build, while typecheck and the unit suite stay green. Night mode's first cut did exactly that, and the browser pass caught it before release. A change to the layout is verified with a production build (`NEXT_DIST_DIR=.next-verify npm run build`), and `theme.test.ts` reads the layout's imports.
- We do not carry a flag across a fold by looking only at the wording that won. `rebuild-rx-habits.js` re-attaches `hidden` / `pinned` by the content of the NEWEST prescription's wording — enough while one signature meant one wording per stored row. When a rule folds two wordings into one habit (the same dose written in Bangla and in English, `ALGO_VERSION` 2, 2026-10-15), a flag set on the older wording was dropped and a dose the doctor had hidden came back. Every wording that landed on the habit is tried, and `hidden` wins. Found before release, from reading the script, not from a failure; the integration spec puts the hidden flag on the OLDER wording because that is the one the newest-wording logic loses, and was checked red against that logic in a copy of the sources.
- We do not keep two copies of the same state in step with one effect each way. The OPD ℞ pad's rows and the prescription's `rxItems` each had their own effect: pad → `rxItems`, and `rxItems` → pad for changes made elsewhere. When two key presses land in ONE render, the first press's copy reaches `rxItems` in the same render as the second press's rows. The `rxItems` → pad effect took that older copy for a change made elsewhere and put it back. The pad → `rxItems` effect then wrote the newer rows again, and the two kept overwriting each other until React stopped the screen. Typing `b`, `m` in a food cell in BAN did it every time in the browser pass (2026-10-15, before release; the unit tests had passed, because `act()` never lands two presses in one render). Now it is one effect (`client/src/lib/usePadSync.ts`): in a render where the pad moved, the pad's edit is the newest and wins. Its test holds the copy back so that it lands in the same render as the next edit.
- We do not let a background fetch believe its own answer is the whole record. The patient fetch beside the ℞ → Drug history mirror (`MuqsitContext.tsx`) used to set `drugHistory` to `p.drugHistory` outright on arrival — safe for every writer that existed when it was written, because each was either that same fetch's own last answer or the ℞ mirror, which re-derives itself from `rxItems` the moment it is disturbed. "+ Add medicine" (2026-10-14) is neither, and so is a line an `incompleteRx` draft has just restored on reload: this fetch is slow enough, on a brand-new or just-edited patient, to land after either — a Distant-past addition on a just-created patient was gone on the very next reload (caught in the browser pass, before release). The handler now merges — the record's own order first, whatever is live beyond it appended, nothing dropped, nothing duplicated once the record catches up — rather than overwriting. A background fetch that refreshes part of the editor is written to merge against live state from the day it is added, not patched once a second writer finds the gap.
- We do not commit a build, and we do not take a commit's message for what it holds. A production build of the doctor app into `client/.next-share`, made to try the app on another PC, went into a commit — 203 MB, two webpack caches of over 90 MB each among it — under the message "Add TypeScript type definitions … update package.json to use ES modules", which described Next's own generated files. The commit before it carried `client/tsconfig.json` as `next dev` rewrites it for the browser suite, which `e2e/README.md` says is never committed. Both were pushed to `origin/siam` with the machine's default identity and taken back out of the branch before reaching `dev` (2026-10-16). `client/.gitignore` now ignores every `/.next*/` folder, whatever `NEXT_DIST_DIR` named it. Before a push, read `git show --stat` of each new commit against its message.
- We do not leave a framework's endpoint answering the internet because the app does not use it, and we do not read `npm audit` by its count. On 2026-10-16 it listed critical remote-code-execution advisories for Next 14 with no 14.x fix. One was in the image optimizer, which neither Next app uses and `next start` serves to anyone; `images: { unoptimized: true }` closes it (`imageOptimizerOff.test.ts`). multer under Nest 10 carried eight DoS advisories on the PUBLIC upload route; an `overrides` entry lifts it, and the route now takes one file and no text field (`server/CLAUDE.md`). The rest is weighed by exposure, not counted (`FUNCTIONAL-AUDIT.md`, "Dependency advisories"): `xlsx` only writes, and `proxy-addr` needs a trusted subnet this app does not configure. The Next 15 and Nest 12 upgrades are still open.
- We do not trust `set -e` across an `&&` chain. `deploy.yml` ran each build as `cd client && npm install && npm run build && cd ..`. `set -e` ignores a failure inside an `&&` list, so a failed build let the script carry on from the wrong directory, skip the builds after it and `pm2 restart all` onto the failure, and the Action reported success. That held for a failed client build, a failed server build and a failed `prisma generate` alike: the workflow's own script, run with stubbed commands, restarted production and exited 0 for each (2026-10-16). Each build now runs in a subshell, the API first, and the same run stops at each failure with exit 1 and no restart.

## Read First
- `docs/DOMAIN.md` — every domain concept (workstation, assistant, supervised doctor, wards, habits, alerts, drug-history mirror…) with the physician's decisions behind it.
- `server/CLAUDE.md` — the access table, scoping rules, auth and upload gotchas; required before any server change.
- `client/CLAUDE.md` — clinical-accuracy rules for alerts, habits, printing, dates; required before any client change. (`admin/CLAUDE.md` for the admin app.)
- `FUNCTIONAL-AUDIT.md` — what works, what is a stub, and the "Open threads" awaiting product-owner decisions; read at session start.
