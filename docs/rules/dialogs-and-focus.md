## At a glance

- A `div` or `span` is never made clickable without `pressable()` (`client/src/lib/a11y.ts`), and no icon-only button ships without an `aria-label`.
- `window.confirm` / `window.alert` are never called in the doctor app: use `confirmAction()` / `tell()`; fix what is being removed before the `await`, re-read the list and the loaded patient after it.
- `inert` — or any attribute React does not manage — is never set through a bare ref: use `useInert()` (`client/src/lib/inert.ts`).
- Nothing is opened over the app without `useDialog()` (`client/src/lib/useDialog.ts`); a new popup's test runs `itKeepsTheKeyboard()`; one that shows an `<iframe>` listens for keys inside it too.
- The focus is never handed back to a button that SAVES: the print sheet closes with the focus on the page (`useDialog(…, { returnFocus: false })`), held by `e2e/tests/print-sheet.spec.ts`.
- A popup that stays mounted for the session never keeps a half-typed value across patients: its draft is dropped when the patient changes, and on close it is ASKED about ("Discard …?", red), never dropped silently.
- ⚕️ The closed patient gate is `inert` (closed to the keyboard too); set `inert` only via `useInert()` (`lib/inert.ts`), never a bare ref; wrappers carry a `key`.
- Anything clickable is keyboard-reachable (`<button>` or `pressable()`); icon-only buttons carry `aria-label`; Investigation calendar arrows MOVE, never choose a date (+4 more)
- Keyboard focus is drawn globally (`:focus-visible` in `app/globals.css`); a control drawing its own opts out with `data-focus-ring="off"`; colours there mirror `theme/index.ts` — change both
- Popups spread `useDialog(open, close)` and prove it with `itKeepsTheKeyboard()`; the Save & print sheet uses `returnFocus: false` — only an opener that commits asks for it (+4 more)
- Use `confirmAction()` / `tell()`, never `window.confirm` / `window.alert`; a removal is `danger` with Cancel holding focus; fix what is removed before the `await`, re-read after (+2 more)

# The rules, in full

## Patterns We Do Not Use

_From the root `CLAUDE.md`._

- We do not make a `div` or `span` clickable without `pressable()` (`client/src/lib/a11y.ts`), or ship an icon-only button without an `aria-label`. 26 controls had no keyboard route and 16 buttons had no name.

- We do not call `window.confirm` or `window.alert` in the doctor app. Use `confirmAction()` / `tell()` (`client/src/lib/dialogs.ts`); the admin console draws its own since 2026-10-09 (`Dialog` in `admin/app/page.tsx`). The browser lets a user switch its boxes off for the page — after that a `confirm()` answers "no" unseen and an `alert()` says nothing, including "the prescription was saved but could not be printed". And because the app's own question does not freeze the page, fix what is being removed before the `await` and re-read the list and the loaded patient after it (2026-10-06).
- We do not set `inert` — or any attribute React does not manage — through a bare ref. Use `useInert()` (`client/src/lib/inert.ts`). React re-uses the wrapper's DOM node for the content it wrapped, and a hand-set attribute stays on it: the editor came back from the patient gate with a patient chosen and nothing in it could be typed into; `Lock` had the same trap (2026-10-06).

- We do not open anything over the app without `useDialog()` (`client/src/lib/useDialog.ts`). A popup that only listens for Escape leaves the focus on the page underneath: with the print sheet covering the screen, three presses of Tab reached the patient chat's message box, where Enter sends. A new popup's test runs `itKeepsTheKeyboard()` (`client/src/test/dialogKeyboard.tsx`), and one that shows an `<iframe>` listens for keys inside it too — a key pressed in a frame never reaches the app (2026-10-12).
- We do not hand the focus back to a button that SAVES. Every popup returns the focus to what opened it, and pressing an opener again normally just opens the popup again — but the print sheet is opened by "Save & print", and with the focus back on it Enter or Space (the key that scrolls a page) filed the same consultation as a second Prescription row. That sheet closes with the focus on the page (`useDialog(…, { returnFocus: false })`); `e2e/tests/print-sheet.spec.ts` holds it with a real keyboard (2026-10-12, caught in review before release).

- We do not keep a half-typed value in a popup that stays mounted for the whole session. On examination's new history boxes held what was typed and not added in local state; the popup is mounted once in the shell, so the text waited there for the next patient, and Save added patient A's history to patient B (review, 18/10/2026). A popup's own draft is dropped when the patient under it changes — and on close it is ASKED about, never dropped without a word (the second review found the first fix did exactly that). The question is about the destructive act ("Discard …?", red): the app's question reads Escape and a press beside it as "no", so "Keep it?" made a second Escape the discard (release review).

## Editor lifecycle (easy to break — know it)

_From `client/CLAUDE.md`._

- The 3.docx mobile gate: nothing is writable until a patient is picked via the mobile lookup (`PatientMobileLookup`, exact 11-digit match, family-tree info rows, "SUPERVISED" badge for other-practice matches). **⚕️ Closed means closed to the keyboard too (2026-10-06).** `PatientGate` was `pointer-events: none` only, so Tab from the mobile box walked into the blurred editor and text landed in the ℞ pad with no patient chosen (DEFECT-E2). The closed gate is `inert` now, like `Lock`. **Both set it through `useInert()` in `lib/inert.ts`, never a bare ref:** React 18 has no `inert` prop, and when the wrapper goes away and the content's root is itself a `<div>`, React re-uses the wrapper's DOM node for it — with the hand-set attribute still on. Seen in the browser the day the gate was made inert: a patient chosen, the editor back, and nothing in it could be clicked or typed into. `Lock` had carried the same trap (a section an assistant was just granted stayed dead until a reload). `useInert` takes the attribute off when React detaches the ref, and both wrappers carry a `key` so the node is not recycled at all. Pinned in `PatientGate.test.tsx` and `Lock.test.tsx` — note those tests pass the content as a **plain element**, as `PrescriptionView` does; wrapped in a component React replaces the node and the trap hides.

## UI conventions

_From `client/CLAUDE.md`._

_These stood under the bullet "Inline styles only" (now in `docs/rules/theme-and-colour.md`):_

  - **Anything clickable is reachable from the keyboard.** A real `<button>` where possible; for a clickable row, card or word, spread `pressable()` from `lib/a11y.ts` beside its `onClick` (it adds `role="button"`, `tabIndex` and Enter/Space, and calls that same `onClick`; `pressable(false)` for a row that cannot be pressed right now). An icon-only button (×, +) carries an `aria-label`. A control whose visible label is the element just before it carries the same text as `aria-label` (the app writes a caption as its own element before the box, so nothing else names the box for a screen reader; what makes a PRESS on the caption reach the box is `lib/captionFocus.ts`, below). In the Investigation popup every result box — number, list or text — is named by `resultBoxName()` (`lib/resultBoxName.ts`): the words on screen first, its field and unit as the catalog writes them, then its TEST — `Hb (g/dL) — CBC`, `Result — HBsAg`, `Organism — Blood Culture`. The visible words lead because someone speaking to the computer says what they can see; the test follows because the caption alone is very often not a name: 671 boxes are captioned `Result`, 138 `Value`, and `Organism` stands in six cultures on one page. A test holds that no two boxes of one category are called the same thing. Until 2026-10-12 the number boxes had no name at all, only their unit as a placeholder that goes at the first digit. **This rule is not yet kept everywhere:** a scan on 2026-10-12 found 46 boxes in 18 files with no name of their own, 20 of them without even a placeholder (the calculators' inputs, most of Profile settings, the sign-in page); listed in `FUNCTIONAL-AUDIT.md`. A modal panel is `role="dialog" aria-modal="true"` with an `aria-label`, and spreads `useDialog(open, close)` (next bullets). Left without a tab stop on purpose: a field's label text that only repeats its `+` button. **⚕️ The Investigation calendar is ONE tab stop (2026-10-12):** each day is a real button that says its whole date, the chosen day holds the stop, and the arrows move ALONG the days from there — left/right a day, up/down a week, Home/End the ends of the month — **without choosing one**. Choosing a day files whatever is half typed under the OLD date first (`handleCalDateChange`), so it stays a deliberate press: Enter, Space or a click. The arrows stop at the ends of the month; another month is its own button. The months in the open list are buttons too (the list could be opened from the keyboard and then nothing in it chosen), and Escape closes the list, not the popup — **from anywhere in the popup** (`handleEscape`, the function the popup gives `useDialog`). Nothing closes the list but choosing a month, pressing its name again or Today, so it stays open while the doctor types a result; listened for on the list alone, and then round the list and the month's name, Escape from a result box still went to the popup — which closed, and files what is half typed on its way out (the second half caught in the second review). Closing the popup closes the list with it, however it was closed — its own buttons, Escape, or another device through device mirroring, which sets `showInvPopup` directly (an effect on that flag; the list's own flag lives in the store, and the list was standing open the next time). What sets the date besides a day: the date box, the month and year steppers, the month list, the year wheel and Today — each a deliberate act, and each files the half-typed result under the old date first. Pinned in `InvestigationPopup.calendar.test.tsx` **with a result half typed**: "the date did not change" proves nothing while there is nothing to file, and the first version of that test would have passed with an arrow key filing the result.

  - **Keyboard focus is drawn globally** in `app/globals.css` (`:focus-visible`, `!important` because inline `outline: none` would otherwise win; text boxes draw it inside their box so the ℞ pad's cells never cover each other). A control that draws its own focus state opts out with `data-focus-ring="off"`. The few colours in that stylesheet mirror `theme/index.ts` — change both.

  - **Popups: `const dialog = useDialog(open, close)` (`lib/useDialog.ts`), spread on the panel (2026-10-06).** It gives every popup the same three things. **Escape** closes it — only the popup on top, and not when a field inside used Escape for itself (`DateField` abandoning a typo calls `preventDefault()`). **Tab stays inside**: past the last control it comes round to the first, Shift+Tab the other way, and focus that is not in the popup at all is brought in — before this, Tab walked out of an `aria-modal` popup into the editor behind the backdrop. It acts only at the two ends, so a popup's own Enter/Tab order is untouched. **Closing puts the focus back** on what opened it, but only when closing left it nowhere, so a popup that hands focus on keeps its choice. Consequence: **whatever a popup shows must be drawn inside its panel** — a list hung elsewhere in the document (a portal) would be unreachable by keyboard; the app has none. The panel takes the focus without drawing a ring (`data-focus-ring="off"`): opting out of the app's ring used to leave the BROWSER's in its place, so a popup opened from the keyboard was outlined whole — in thick amber on Android — until `globals.css` took that off too (2026-10-09). **Every popup that opens over a patient's record is on the hook since 2026-10-12** — the last four were the print sheet, the image viewer, special advice and the personal note, which closed on Escape by themselves and gave the keyboard nothing else. **Two overlays are NOT on it yet**, both in `WorkstationSwitcher.tsx`: the "Your workstations" drawer and the wall shown to a secondary account with no practice to work in (`FUNCTIONAL-AUDIT.md`). What that cost, measured in the browser with the print sheet open: the focus was left on the page underneath, three presses of Tab reached the patient chat's message box (where Enter SENDS) and fifteen reached the navigation, all behind a sheet covering the whole screen. **A new popup proves the same things with `itKeepsTheKeyboard()` from `src/test/dialogKeyboard.tsx`**, run against the real component: Tab wraps at both ends, focus left behind is brought in, Escape closes once, a question raised over it owns Escape, opening takes the focus and closing gives it back. Two things that file taught: a popup with a second popup INSIDE it gives each its own `useDialog` (the personal note's "how should it be printed?" — the last dialog in the document is the one on top, and that is the inner one), and **the print sheet's frame needs its own key listener** — a key pressed while the focus is inside an `<iframe>` never reaches the app's document, and after Print the focus is always inside it. `PrintSheetModal` hands Escape to the app's document (so the on-top rule applies), sends Ctrl/Cmd+P to the sheet's own Print and brings Tab back to its two buttons; the listener is put on after every `document.write`, because `document.open()` drops the ones before it, and nothing is added to the sheet's HTML (a test compares the frame, element for element, with a bare frame given the same string; another holds that the app re-rendering round the sheet does not write it again, since a second write would lose where the doctor had scrolled to and run the sheet's fitting again). **⚕️ One popup does NOT give the focus back: the print sheet opened by "Save & print"** (`useDialog(…, { returnFocus: false })`, through `PrintSheetModal`'s `afterSave`). That button SAVES. With the focus put back on it, Enter or Space — the key that scrolls a page — files the same consultation as a second Prescription row (the server does not dedupe), and Enter held down on the sheet's Close does it with no second press; measured in a browser before release, the focus was on that button after Close. Before the sheet was on the hook the focus ended on the page, and for this one route it still does. "Preview PDF" saves nothing and gets its focus back like any popup. Ask for `returnFocus: false` only for an opener that commits something; the hook takes the option when the popup OPENS, with the opener it is about, so a popup that drops it in the very update that closes it still does not hand the focus back. The sheet itself is one of the popup's Tab stops once it is written (Print → Close → the sheet → Print; `tabIndex` on the frame, because the hook keeps Tab on the stops it knows and a frame is not one unless it says so), so it can be scrolled from the keyboard before it is printed. All of this is run with a real keyboard in `e2e/tests/print-sheet.spec.ts` — jsdom has no focus inside a frame. Known gap: while the keyboard is in the sheet, nothing is drawn to say so. Titles are `dialogTitle`, the veil is `scrim`, a screen's name is `pageTitle` (all `@/theme/styles`).
  - **⚕️ "Are you sure?" and "this did not work" are `confirmAction()` / `tell()` from `lib/dialogs.ts` — never `window.confirm` / `window.alert` (2026-10-06, seventeen replaced).** The browser's box is titled with the site's address, and after the second one it offers "Prevent this page from creating additional dialogs": tick it and every later `confirm()` answers *false* unseen and every later `alert()` says nothing — among them "Prescription saved, but the printable sheet could not be built" and "2 images were NOT added: a different patient was opened". `confirmAction({ title, body, confirmLabel, danger })` resolves `true` only on the confirm button; the title names the thing ("Remove Rahim from Ward 3?") and only what is really there — deleting a ward with nobody on it does not ask about "its team of 0" — the button is its verb, a removal is `danger` (red `btnDanger`, and **Cancel holds the focus** so a stray Enter keeps what was there). `tell({ title, body, tone })` is a message that must be read: it stays until OK, a click on the backdrop does not dismiss it, and the same message raised again while waiting is one message. `components/common/DialogHost.tsx` draws them, mounted once in `Providers`, above every popup, one at a time; Escape is that box's alone. **The question is never skipped:** with no host on the page (a unit test, a screen outside the providers) both fall back to the browser's box, and a host that leaves answers an open question NO. **⚕️ `confirmAction` is asynchronous and the page stays live behind it, which `confirm()` never allowed.** Fix WHAT is being removed before the `await` (the ids, the ticked set) and re-read anything that can change after it: the family tree takes the relative off the list as it is *then* (`live` ref in `PatientSettingsView` — another device may have added one meanwhile, and writing the older list back would drop them), and the photo, the family tree and the supervising-doctor list all do nothing if another patient was opened while the question was on screen. Pinned in `dialogs.test.tsx` and `PatientSettingsView.regression.test.tsx`.
