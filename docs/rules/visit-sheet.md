## At a glance

- Disease/Surgical history (sidebar History row) are the PATIENT's: written to the server at once, listed only from its answer; × is soft with Undo; never printed as none when unread (+4 more)
- App's own not-found / error / loading screens; `app/error.tsx` says only what is true; the first two use hard-coded colours and import no theme so they render when app modules fail
- How it works — Note and Plan are two separate sidebar lists (one "Note / plan" field before)
- `Prescription.plan` is a new additive column; nothing was moved out of `note` — old prescriptions read back and print under "Note" exactly as written
- Note and Plan both carry `rx.note` via explicit `permKey`; never put "Plan" into `PERM_KEY_OF_LABEL` (IPD label); a label colliding across screens must pass `permKey`
- `CONDITION_FIELDS` in `lib/rxAlerts.ts` lists "Note" and "Plan"; an unlisted label silently stops firing contraindication alerts
- How it works — Note and Plan are both `inlineEdit` fields and print as two sections on the sheet
- In-place edit (`inlineEdit`): ✎ Edit opens all entries as staged boxes; a blanked box is a mis-key, not a deletion; each field's boxes are their own group; IPD never passes it (+2 more)
- OPD sidebar line removal: red ✕ only inside ✎ Edit, never on a line being read; one press takes ONE line, Undo puts it back at its old place and never writes a line twice (+2 more)
- Every OPD `ExpandableField` (incl. History, Associated illness, Advice) edits in place; popup ADDED chips show × only after ✎ Edit; IPD unchanged; supersedes parts of the in-place/removal bullets
- Final diagnosis "Previous diagnosis" panel (`previousItems`): a tick only stages text, Cancel writes nothing, no past prescription touched; Select all / Clear are BUTTONS, never a tickbox (+2 more)
- `onExaminationSummary` is written by the server only, under `ROW_LOCK_TX`: append, and SOFT remove/restore of `Disease Hx:` / `Surgical Hx:` entries by kind + words; findings cannot be removed.

# The rules, in full

## UI conventions

_From `client/CLAUDE.md`._

- **Disease history and Surgical / intervention history: MOVED from On examination to the sidebar's History row (physician's sheet 28/10/2026, item 7; 02/11/2026).** `components/prescription/PatientHistoryField.tsx` wraps History's `ExpandableField` (this visit's lines, untouched) and adds the patient's two lists under it in the popup's format — a text box with the popup's placeholder, a Date box (`151026` → `15/10/2026`, `historyEntryText` in `lib/oeHistory.ts`: four-digit year, only a date that has happened) and Add. **They are the PATIENT'S, not the visit's:** Add writes at once to the server (`patientsApi.appendOnExamination`, one `Disease Hx: <text>` / `Surgical Hx: <text>` entry at this visit's date — the line the popup wrote, so the records page's section and every old entry keep working), and the list on screen is the server's answer, taken only while that patient is still loaded (`patientIdRef`). Nothing is listed before the server has it; the boxes are locked while it is on its way and cleared only after; a failure is a `tell()` box and the text stays. A repeat (same words, case and spacing aside) is refused in words. × asks (`confirmAction`, red), takes it off SOFTLY (`/on-examination/remove`, `removedAt` / `removedBy` on the server) and offers Undo (`/restore`); every reader leaves a removed entry out (`isRemovedOe`: this field, `diseaseSurgicalHistory`, `groupOeForRecords`). The lists are keyed by the patient (nothing half-typed, no Undo, reaches the next one). They are drawn from the record (`onExaminationSummary`) and its `recordStatus`: "Loading history…" while it is on its way, a `LoadError` with Try again (`retryRecord`) when it did not come — never an empty list. Gated by History's own key (`canEditLabel("History")` → `rx.history`): without it the lists are read-only, with no boxes, no × and no ⊘. **⊘ Hide** (`hideHistory`, `HideToggle`, top right of the row) keeps the WHOLE History section off the printed sheet; OFF by default (History always printed), rides the draft, `incompleteRx` and the device mirror, `resetEditor` sets it back to false, and joins `visitSig` only when set. The sheet's History is `printableHistory(history, patientHistory(list), hideHistory)` — the visit's lines exactly as before, then `Disease Hx: …` / `Surgical Hx: …` in the order first written; the list is read again at Save & print / Preview (`historyForPrint` in `PrescriptionView`), the copy on screen when that fails, and with no copy at all the doctor is asked ("Print without it" / "Go back") — never printed as none. `prescriptionDoc.ts` is unchanged. **The On-examination popup no longer has the boxes** (one fact in two editable places would have let a Save & print re-append what the sidebar removed). A visit parked before the move still carries them in `oeData`: the popup shows them read-only and still writes them into the visit's lines on Save, as before (`OePopup.history.test.tsx`). Pinned in `PatientHistoryField.test.tsx`, `lib/patientHistory.test.ts`, `MuqsitContext.test.tsx` (History ⊘ Hide, recordStatus), `RecordsHistorySections.test.tsx`.

_These stood under the bullet "Inline styles only" (now in `docs/rules/theme-and-colour.md`):_

  - **The app's own screens for the three moments Next would otherwise fill in:** `app/not-found.tsx` (a wrong address), `app/error.tsx` (a screen that threw while rendering — it says only what is true: saved data is unchanged, and the editor restores its last auto-saved draft) and the branded loading screen in `components/auth/guards.tsx`. The first two use hard-coded colours and import no theme, because they must render when the app's own modules are what failed. `app/icon.svg` is the tab icon.

- **Note and Plan are two separate sidebar lists** (physician's decision, **2026-09-07**). They were one field, "Note / plan", until then. What the split does and does not touch:
  - **`plan` is a NEW column** (`Prescription.plan`, `manual-prescription-plan.sql`), additive and empty on every existing row. **Nothing was moved out of `note`** — which of a stored line was a note and which was a plan is a clinical judgement, not a string rule, so old prescriptions read back exactly as they were written and print under "Note".
  - **Both fields still carry the ONE permission key the combined field had, `rx.note`,** and they name it explicitly (`LeftField.permKey` → `ExpandableField`'s `permKey`) instead of being gated by their label. `canEditLabel` is a LABEL lookup and **"Plan" is also the IPD clinical sheet's own label** — putting "Plan" into `PERM_KEY_OF_LABEL` would start gating the IPD field on an assistant key, and assistants reach IPD with no `ipd.*` key at all, so it would revoke something they can do today. A new field whose label collides across two screens must pass `permKey`, not add a map entry. The assistant editor's row now reads **"Note & plan"**; the KEY string is untouched, so no grant was lost.
  - **`CONDITION_FIELDS` moved with the label.** `lib/rxAlerts.ts` listed "Note / plan"; it now lists "Note", and "Plan" was already there for the IPD sheet and covers both screens. An unlisted label silently stops firing contraindication alerts — this is the same trap the IPD "Sign"/"Symptoms" rename documents below.
  - Both are `inlineEdit` fields (next bullet) and print as two sections on the sheet.
- **Chief complaints, Provisional diagnosis, Final diagnosis, Note, Plan and (on the ℞ side) Advised tests / investigation are corrected IN PLACE — and they are the only fields that are** (`ExpandableField`'s `inlineEdit` prop, physician's decisions 2026-08-28 for Final diagnosis, **2026-09-01** for Chief complaints and Provisional diagnosis, **2026-09-07** for Note and Plan, **2026-09-25** for Advised tests — "edit like Chief complaints"; `RightColumn` reads `isInlineEditField` for that one label, and its `+` still opens the tabbed popup with directories and groups). The opt-in list is `lib/inlineEditFields.ts` (`INLINE_EDIT_FIELDS` / `isInlineEditField`), read by `LeftColumn`, and pinned in `inlineEditFields.test.ts` — those are the lists a doctor re-reads and re-words with the patient still in front of them, so the correction must not cost a modal. **`isInlineEditField` is read by `LeftColumn`, and by `RightColumn` for Advised tests only**, which is what keeps "Plan" on the popup in the IPD sheet while the OPD one opens boxes; `IpdDetailView` never passes `inlineEdit`. The ✎ Edit button sits beside the `+` as on every other field, but here it does not open the popup: it turns **every entry at once** into an editable box, in place, and **Enter in any box finishes the whole edit** (the button reads ✓ Done while they are open and does the same). Escape abandons the edit; leaving the group — clicking anywhere outside the boxes — saves it, so a typed correction cannot evaporate; moving between the boxes keeps it open. Double-clicking a line opens the same boxes with the caret on that one. The first shape of this (2026-08-28, superseded within the day) had no Edit button and opened one line per double-click; the physician asked for the button back and for the whole list to open together, because a list is read and corrected as a list. Every other clinical list — Previous complaints, History, Investigation report findings, Drug history, On examination, Associated illness, RightColumn's Advice, and all of the IPD sheet (including its own "Advice tests") — keeps the popup behind that same-looking button, so the prop stays opt-in and must not be widened without asking. **Each field's boxes are their own group** (`data-inline-edit-group` carries a per-instance `useId`): the marker used to be a bare attribute shared by every field, which — once more than one field could open boxes — made "moved on to the next field's ✎ Edit" look like "still inside this field", and the correction just typed was dropped instead of saved. Pinned by the side-by-side cases in `ExpandableField.test.tsx`. Two rules hold the safety line: **a blanked box is a mis-key, not a deletion** (that line keeps what it had — removing a diagnosis stays a deliberate act in the `+` popup, which is why that button never goes away), and the boxes are a **staged copy**, so nothing reaches the field until the edit is finished. A line whose new text is not already in the list is logged to the activity feed and remembered as a recent entry, exactly as the popup does. Pinned in `ExpandableField.test.tsx` (jsdom), including that the other fields still open the popup and ignore a double-click.
- **⚕️ Taking one line off the OPD clinical sidebar — inside ✎ Edit only (physician's sheet, 15/10/2026, item 4: "cross delete koro, ageo bolsi accidental delete hoa jabe").** From 2026-09-25 to that sheet a grey × stood beside every line, always, and one click took the line off; it caused accidental deletes and is gone. A line being READ carries no ×. `ExpandableField`'s opt-in `removable` now draws a red round ✕ beside each BOX of a field corrected in place (✎ Edit open — Chief complaints, Provisional/Final diagnosis, Note, Plan, and Advised tests in `RightColumn`); the ✕ sits inside the edit group, so pressing it never trips the boxes' "left the group → save" blur, and the staged boxes lose the same line, so what is typed in the other boxes stays with its own line. A popup field (History, Associated illness) takes a line off from its chip in the popup that its ✎ Edit opens, as it always has. What follows is the rule as it was and still is for the ✕: `LeftColumn` passes `removable` for Chief complaints, History, Note, Plan, Provisional/Final diagnosis, Associated illness. One press takes off that ONE line (by position, so a repeated line loses only the copy clicked), and a "Removed “…” · Undo" bar puts it back **at its old place**; it stays until undone, dismissed or replaced by the next removal. **⚕️ Undo never writes a line twice (16/10/2026):** a line written back (from + or by hand, capitals and spacing set aside) takes the bar away and Undo does nothing — `Pregnant` taken off, `pregnant` added again, and Undo pressed had left both. The bar remembers how many copies stayed, so a line that was in the list twice can still be put back; it is derived on each render, not cleared by an effect. Not offered to an assistant who cannot edit the field (they cannot open ✎ Edit); the Undo bar stays up through the end of the edit. This does NOT change the in-place edit rule above: a blanked box is still a mis-key, not a deletion — the ✕ is the deliberate act. Investigation findings, On examination and Drug history are other components and are unchanged; `RightColumn` passes it to Advised tests / investigation too (same day, with the in-place edit); the IPD sheet and Advice do not opt in. Pinned in `ExpandableField.remove.test.tsx`.
- **⚕️ OPD templates carry Advice and Advised tests (physician, 24/11/2026).** `PrescriptionTemplatesView`'s editor shows, for the OPD category only, the SAME `ExpandableField`s as `RightColumn` (Advice with `learnedSource="advice"` and BAN typing; Advised tests with the directory and groups), each with its circled + like ℞ — so the doctor's learned lines and recents are offered exactly as on the prescription (IPD and custom templates stay medicines-only and never send `advice`). They are stored on the template (`advice`, `adviceTest`; `manual-template-advice.sql`, applied BEFORE the release — every template read selects them). Clicking a template adds its advice and tests AFTER what the visit has (`withTemplateLines`: blanks skipped, a line already there or repeated is written once, text untouched), and a section the user may not edit (`rx.advice` / `rx.adviceTest`) is left alone. A template of advice or tests alone is allowed. Pinned in `rxTemplates.test.ts`, `PrescriptionTemplatesView.advice.test.tsx`, `server/test/templates-advice.int-spec.ts`. Not verified in a browser (the shared database did not have the columns when this was written).
- **⚕️ 31/10/2026 — every OPD list edits in place; the popup's chips need ✎ Edit for their × (physician's sheet: "Sob jaigai edit … final diagnosis a jevabe ase", "cross sign available thakle accidental delete hoa jete pare").** This SUPERSEDES the "only fields that are" and "Advice does not opt in" parts of the two bullets below: `INLINE_EDIT_FIELDS` now also holds History, Associated illness and Advice, so every `ExpandableField` of `LeftColumn` and `RightColumn` has + and ✎ Edit (boxes in place, ✓ Done, red ✕ per box only while editing, Undo). `RightColumn` passes `inlineEdit` + `removable` to Advice. The IPD sheet is unchanged (its labels are not on the list; the physician named the prescription's lists). In every `ExpandableField` popup the ADDED chips carry no ×; a "✎ Edit" at the right end of the ADDED heading (`aria-pressed`, reads "✓ Done editing" when on) shows it, and it is off at each opening. Removal there is still staged (Cancel keeps all). **24/11/2026 (physician): that popup ✎ Edit now turns every typed chip into a text box with its red ✕, as on the page** (`chip-edit-<n>`; Enter finishes the edit, not the popup; a box left blank gets its old text back via `chipSnap` — only ✕ removes; edits stay staged until Done, Cancel discards them). Pinned in `ExpandableField.remove.test.tsx`. A ticked quick-pick (Associated illness' BA/COPD/…) is still unticked as before. Pinned in `ExpandableField.everywhere.test.tsx`, `inlineEditFields.test.ts`.
- **"Previous diagnosis" — the patient's past diagnoses, ticked into today's list** (`previousItems` prop, physician's decision 2026-08-28). The Final diagnosis popup grows a right-hand panel headed **Previous diagnosis** ("From this patient's past visits"): every final diagnosis from ALL of this patient's saved prescriptions (`usePreviousDiagnoses`, newest visit first, repeats folded case-insensitively keeping the newest spelling), each with a checkbox, plus an `n/total` count. The heading spells the words out — the physician asked for the full name, not the "P.D" abbreviation they sketched it with. **Select all / Clear are BUTTONS, never a tickbox** (2026-08-28, from the physician's report): a select-all checkbox that mirrors the rows below ticked itself the moment the one diagnosis in the panel was picked, which reads as the system having chosen. `Clear` only appears once something is ticked, and `Select all` greys out when everything already is. **Only the list scrolls** — the heading and the action row sit outside the scroll box, so a patient with a long history never pushes `Clear` out of reach (`pd-list`, pinned in the test). It is a shortcut for retyping and nothing else — a tick only stages the text like any other draft entry, so **Cancel still writes nothing** and no past prescription is ever touched. `Select all` / `Clear` move only the panel's own lines, leaving what the doctor typed this visit alone. The panel is absent (and the modal stays 520px, growing to 760px only when it appears) for a patient with no past final diagnosis, and P.D entries are filtered out of the SUGGESTIONS row below so the same text is not offered twice. It reuses the `["prescriptions", patientId]` query key that `PreviousComplaintsField` already fetches, so opening a patient costs one request, not two. Deliberately **not** wired to Provisional diagnosis or the IPD sheet — `previousItems` is a separate opt-in from `inlineEdit` and stayed Final-diagnosis-only when the in-place editing was widened on 2026-09-01, because it is a carry-forward picker, not an editor (Chief complaints already has its own **Previous complaints** field for that job).

## Prisma specifics

_From `server/CLAUDE.md`._

- **`onExaminationSummary` is written by the server only, under the row lock (`ROW_LOCK_TX`):** `POST /patients/:id/on-examination` APPENDS (31/10/2026), and since 02/11/2026 `POST /patients/:id/on-examination/remove` and `/restore` take a `Disease Hx:` / `Surgical Hx:` entry off SOFTLY and put it back (`setHxRemoved` in `patients/on-examination.ts`; the sidebar's History block, physician's sheet 28/10/2026 item 7). A removed entry stays in the array with `removedAt` (ISO) and `removedBy` (the practice doctor's name, never a client's word); every client reader leaves it out (`isRemovedOe`), and the append does not count it as "already there", so the same words written again are a new entry. An entry is named by kind + its words (case and outer spacing aside), not by index or id, so entries from before the change (no id) can be named, and every copy of the same history (written at two visits) goes together. Same reach as the append: the owner's practice AND a supervising one (`accessibleWhere`); an assistant needs any `rx.*`. Nothing to do is a 409 in a doctor's words. Only those two prefixes can be named — an examination finding cannot be removed. `on-examination.spec.ts`, `test/on-examination-append.int-spec.ts`.
