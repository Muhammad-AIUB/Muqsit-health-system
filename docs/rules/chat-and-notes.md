## At a glance

- No second copy of loaded data is kept for a button to act on: the personal note has ONE text — what was typed, else what is saved — and a save clears only what it SENT.
- An open popup never follows the editor's patient: a popup that writes to a patient is opened FOR that patient (id and details fixed at the press), and its opener does nothing while it is open.
- A field's report of its own text is never taken as an edit (the note's editor reports on every blur): compare with what is held before calling anything changed.
- Revision Notes: held text is only ever sent while its OWN user is signed in; every save and read names `expectedUserId` and the server refuses others; a save clears only what it sent (+5 more)
- Personal note is private: never add to `mirrorSnapshot`, draft, `incompleteRx`, feed or print; ONE text; box fixed to the patient at the press; sensitive mark stays a link (+4 more)
- `DoctorPatientNote` is read/written only under `@CurrentUser().id`; `@WorkstationDoctorId()` only proves reach — do not "fix" it to the workstation doctor, never log it to `activity`.
- `ActivityService` takes an already-resolved `doctorId` and must never resolve a practice itself; `detail` capped at 400 chars — trim free text (+1 more: log clinical input).

# The rules, in full

## Patterns We Do Not Use

_From the root `CLAUDE.md`._

- We do not keep a second copy of loaded data for a button to act on. The personal note held a `draft` that an effect copied the loaded note into, with a "changed" flag beside it. The copy arrived one render late — Print pressed in that instant printed an empty note and skipped the question a note with sensitive text must ask; no hand is that fast, a test was, one run in four, and `scripts/test-repeat.mjs` is what named it: a test whose outcome varies is telling the truth about the code. And Save marked everything "saved", also what was typed while the request was on its way: those words were thrown away, or left on the screen looking saved while Print read the older text. The note has ONE text — what was typed, else what is saved — which the box shows, Save sends and Print prints; and a save clears only what it SENT (`client/src/components/prescription/PersonalNote.tsx`, 2026-10-12).
- We do not let an open popup follow the editor's patient. The personal note was handed `currentPatientId` on every render; another device moving the editor on (device mirroring), or a patient still loading from the OPD queue, changed it under the open box — and words typed for one patient were saved into the next one's note, under the next one's details. A popup that writes to a patient is opened FOR that patient: the id and the details are fixed at the press, and it stays theirs until it is closed (fourth review; in production until the release that carried this). The button that opened it does nothing while it is open — it is still in the page behind the popup, where a screen reader or a voice command can press it, and pressed again it re-pointed the open box at whoever was in the editor (fifth review).
- We do not take a field's report of its own text as an edit. The note's editor reports on every blur, typed in or not, and an untouched note asked about unsaved changes; compare with what is held before calling anything changed.

## UI conventions

_From `client/CLAUDE.md`._

- **Revision Notes (sheet item 4) — `components/tabs/RevisionNotesView.tsx`, tab `revision` at `/revision-notes` (`TRAILING_TABS`, after BAN / EN and ☀ / ☾; a card on the phone's More).** The signed-in user's own notebook (server: keyed by the authenticated user, `server/CLAUDE.md`). `RichTextEditor` with highlight, no images (an upload is a public URL). Same text rules as the personal note: ONE text (`edited ?? saved.html`), a save clears only what it sent (`afterSave`), it saves itself 2 s after typing stops and on leaving the tab, `beforeunload` asks with unsaved text, and a 409 (another screen saved since) keeps the typing and offers "Show that version" behind `confirmAction` (which says so when that version cannot be loaded). Saves go one at a time (`enqueue`), each over the copy the last one left; text still unsaved when the tab is left is HELD in memory for the signed-in user and saved after whatever is on its way, and is back on the page on return if that save fails (review, 18/10/2026: it was lost). Held text keeps whether it was REFUSED, and on return it is a conflict — never an ordinary edit — when it was refused or the server's copy changed while the tab was away (second review: leaving the tab and coming back got round a 409). While anything is held the page asks before it is left, it is tried again on `online`, and `logout()` saves it first through `lib/beforeLogout.ts` (sent after the server's logout it was a 401). **Held text is only ever sent while its OWN user is signed in** (`lib/signedInUser.ts`, kept by `AuthContext`): on a shared PC one doctor's held notes went out under the next user's session and became that user's notebook (release review). **That guard cannot see a sign-in on another TAB, which shares the login cookie, so every save AND every read names its user (`expectedUserId`) and the SERVER refuses either one for anyone but the session's own** (409, `code: SIGNED_IN_USER_CHANGED`, read into `ApiError.code` by `apiFetch`): a refused save keeps the typing, stops the saving-by-itself as a 400 does (Save tries again), and never offers "Show that version"; held text refused so stays held, not a conflict. A refused READ shows no notebook ("Your Revision Notes are not shown here.", the server's sentence, Try again) and never sets `saved` / `lastSaved`, and held text stays held and is shown read-only beneath to be copied — the first version read without the check, and coming back to the tab showed the other account's notebook and offered it in place of the held typing (release review of a2d7b93). Saving by itself backs off after each failure (2, 4, 8 … 60 s). A notebook over `REVISION_NOTES_MAX` (2,000,000 characters — the DTO's limit; Bangla is 3 bytes a character, under the 8 MB body limit) is refused on the screen, and a 400 / 403 / 413 stops the saving-by-itself until the doctor types again. Pages: drawn A4 wide with a dashed line and "Page N" every 1123 px of writing (`PAGE_HEIGHT_PX`), counted beside the search. Ctrl+F (while the tab is open) puts the cursor in the app's own search box; matches are counted, Enter / Shift+Enter step, the current one is scrolled to and marked with the CSS Custom Highlight API where the browser has it (counted and scrolled to without it). Print prints the notebook alone, through `sanitizeHtml`. `lib/revisionNotes.ts` (+ test), `RevisionNotesView.test.tsx`, `layout/revisionTab.test.tsx`.
- **🔒 My Personal Note for This Patient (2026-09-24)** — `components/prescription/PersonalNote.tsx`, rendered at the bottom of `LeftColumn`. Private to the signed-in user (the server enforces it — never add it to `mirrorSnapshot`, the draft snapshot, `incompleteRx`, the activity feed or the printed prescription). Patient details come from the header fields until the first save, then from the stored, frozen `patientInfo`. The note is HTML from `RichTextEditor` (opt-in `highlight` — a TOGGLE since 2026-09-25: it reads the inline background via `lib/highlight.ts` because Chrome's `queryCommandValue("hiliteColor")` returns `""`, and with only a caret inside a highlight it unmarks that whole run; before this a highlight could not be taken off — and `allowImages={false}` because an upload is a public URL) and is passed through `lib/safeHtml.ts#sanitizeHtml` wherever it is rendered or printed. Print writes `personalNoteHtml()` — this note alone — into a hidden iframe. **Sensitive information (2026-09-25):** `RichTextEditor`'s opt-in `sensitive` marks text as `<a href="mhs-sensitive:1">` — the ONE link `sanitizeHtml` keeps (href exact, every other attribute dropped; every other `<a>` is still unwrapped), styled by `lib/sensitive.ts#sensitiveCss` (inert — `pointer-events: none` — in the saved view and the print), never an inline background, so the highlighter can never read or clear it. **⚕️ Why a link and not a span — do not "simplify" it back.** A `<span data-sensitive>` was tried first and failed twice in Chrome: `execCommand("insertHTML")` treats a span as a disposable style wrapper and, inside a line, rewrote it to a plain coloured span (or dropped it) — text that LOOKED marked but was not, and printed under "without" (found by the second review round); and hand-made DOM edits kept the span but broke Ctrl+Z, which then deleted the doctor's unmarked words. With a link, a selection is marked by Chrome's own `createLink` (one link per line, on the undo stack) and unmarked by `unlink` (splits exactly around the selection); both, plus Backspace/Delete joins, bold, font, highlight on/off and Remove Formatting, were checked in Chrome and keep the mark. Typing mode inserts a link holding TWO zero-width spaces with the caret between them — Chrome never extends a link typed at its edge, so the caret must never sit there; turning it off moves the caret after the link, where typing is plain. Enter inside a run inserts a `<br>` so the next line stays marked. The zero-width spaces are stripped by `sanitizeHtml` and ignored by `isBlankHtml`/`hasSensitive`. `personalNoteHtml(…, { sensitive })` **defaults to leaving the marked text OUT** (`stripSensitive`), so a caller that forgets to ask never prints it; Print asks only when `hasSensitive()` finds visible marked text. Pinned in `PersonalNote.test.ts` and `safeHtml.test.ts`. **The same text is not a change (2026-10-12):** `RichTextEditor` reports its text on every blur, typed in or not, and the note took each report as an edit — tabbing through an untouched note made it ask about unsaved changes that did not exist. `onChange` now ignores a report equal to the draft; typed text is still asked about before it is thrown away (`PersonalNote.keyboard.test.tsx`). **⚕️ The note has ONE text, and the box is ONE patient's (2026-10-12, fourth review).** Three defects, the second and third in production until the release that carried this, none of which a test had been able to see — so `PersonalNote.box.test.tsx` now presses the real buttons and reads the real print frame. (1) **One text:** what has been typed since the note was loaded or last saved, and until something is, the saved note (`edited ?? saved.html`). The box shows it, Save sends it and Print prints it; nothing reads anything else. It used to be a `draft` that an effect copied the loaded note into, beside a separate "changed" flag: the copy arrived one render late, and Print pressed in that instant printed an EMPTY note and skipped the sensitive-text question (it could not leak — the draft was empty — and no hand is that fast; three tests were, one run in four, until `scripts/test-repeat.mjs` named them). (2) **A save clears only what it SENT.** The box stays open for writing while the request is on its way, and Save used to mark everything saved when the answer came — so words typed in that time were thrown away when the saved note was copied back in, or, when the text sent was the text already saved, stayed on the screen looking saved and were lost on Close with no question asked. They stay now, the editor stays open, and Save can be pressed again. (3) **The box is opened FOR a patient** — `PersonalNoteSection` fixes the patient's id and the header's details at the press — **and is that patient's until it is closed.** It used to be handed `currentPatientId` on every render, and that changes under an open note when another device picks the next patient from the search box (device mirroring) or a patient chosen from the OPD queue finishes loading: the box then showed the next patient's details over the words typed for the first, Save wrote them into the next one's note, and a print question asked about one note printed the other. `e2e/tests/personal-note.spec.ts` runs it with two real browsers and the real mirror stream — on the old code the open box read "Patient Name: Note Patient Beta" over "Made-up words about Alpha". **Consequence to know:** an open note no longer follows the editor to the next patient; close it and open it again for whoever is loaded now. **The button that opens the note does nothing while one is open:** it stays in the page behind the note — out of a mouse's reach and of Tab's, but a screen reader or a voice command can press it, and it carries the note's own name — and pressed with another patient in the editor it re-pointed the open box at that patient, typed words and all (fifth review, before release). Also held by `PersonalNote.box.test.tsx` since then: a saved note shows and prints its OWN details, as they were at its first save, not the header's of today; Save cannot be pressed a second time while a save is on its way; and the "Unsaved changes" line goes once they have been saved (it used to stay, under a note with nothing unsaved in it). **Not covered, and unchanged:** when the other device CLEARS the editor (New Prescription, or its own Save & print) or moves to another tab, `PatientGate` / the tab router redraw this device's editor and the note closes with it — words typed and not saved are lost without a question (`FUNCTIONAL-AUDIT.md`). Keeping the note through that means holding it above the editor, which is a change of its own.

## ⚠️ `patient-notes` — keyed by the SIGNED-IN USER, on purpose (2026-09-24)

_From `server/CLAUDE.md`._

`DoctorPatientNote` (`manual-doctor-patient-note.sql`, applied 2026-09-24) is the
one patient-scoped table that is NOT keyed by the workstation doctor: the
physician's rule is that a personal note is visible to the person who wrote it
and nobody else — not an assistant in the owner's workstation, not the owner
reading an assistant's. So `@CurrentUser().id` is the ONLY key a note is read or
written under, and `@WorkstationDoctorId()` is used for one thing: proving the
patient is reachable through `PatientsService.get` (404 otherwise). Do not
"fix" this to the workstation doctor, and never log it to `activity`.
`patientInfo` is written on create only. Pinned in `patient-notes.service.spec.ts`.

## Gotchas

_From `server/CLAUDE.md`._

- Activity log (`activity`) is the doctor-facing audit trail; when adding a feature that records clinical input, log it (`section`, `detail`, optional `imageUrl`) so it appears in "Notifications, Chats & Reports". `detail` is capped at **400 chars** — trim free-text names (a chief complaint is doctor-typed) before interpolating, or the whole log call 400s. **`ActivityService` takes an already-resolved `doctorId` and must never resolve a practice itself.** It used to re-derive one from what it treated as a user id (`Assistant where assistantId = …`); because the controller passes `@WorkstationDoctorId()`, a doctor who ALSO assists someone else silently read and wrote the OTHER practice's feed — patient names and clinical detail across the boundary Rule 1 exists to hold. Fixed 2026-08-27 (CSO audit) and pinned by `activity.service.spec.ts`, which asserts `prisma.assistant` is never touched. The general rule: **`WorkstationGuard` is the only place allowed to decide whose practice a request acts on** — a service that resolves it again is a second, unreviewed answer to the same question.
