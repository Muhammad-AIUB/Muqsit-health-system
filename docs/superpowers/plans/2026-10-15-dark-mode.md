# Night mode (doctor app) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A ☀ / ☾ toggle in the doctor app's header that switches the whole app to an eye-friendly dark-grey night palette, with light mode unchanged.

**Architecture:** Every `C` colour becomes `var(--c-<hue>-<shade>, <today's hex>)`. One generated `<style>` (built from the same palette file) defines the variables for light under `:root` and for night under `html[data-theme="dark"]`. A small store (`lib/theme.ts`, like `lib/kbdLang.ts`) flips the attribute. An inline script sets it before the first paint. Raw colours in components are moved onto tokens, and a scan test keeps them there. Printouts, patient images and rich-text "paper" never darken.

**Tech Stack:** Next.js 14 App Router, React 18, Vitest + Testing Library (jsdom).

## Global Constraints

- Spec: `docs/superpowers/specs/2026-10-15-dark-mode-design.md`.
- Light mode must be pixel-identical: every light token equals today's hex.
- Night: page `#16181B`, card `#1F2226`, body text `#E3E6EA`. Every drawn text/background pair passes WCAG AA 4.5:1 in BOTH modes.
- Never darkened:
  - `lib/prescriptionDoc.ts` (no edits at all);
  - every printout (personal note, investigation download, html2canvas snapshot);
  - patient images;
  - the image viewer's black backdrop;
  - rich-text editing and viewing surfaces ("paper").
- Toggle:
  - per user per device, `mhs_theme:<userId>`;
  - the device's last choice is kept in `mhs_theme`;
  - default light; not mirrored.
- Icons come from `components/common/Icon.tsx`, never an emoji. An icon-only button carries an `aria-label`.
- No third-party script or stylesheet. The inline pre-paint script is first-party.
- Reply to the physician in Bangla; code and comments in English.
